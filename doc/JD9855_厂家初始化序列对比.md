# JD9855 厂家初始化序列与当前驱动对比

核对日期：2026-09-28。基于当前工作区文件，不根据驱动 IC 名称猜测寄存器含义。

厂家文件：`doc/BOE1.8-N81_JD9855_360x360_initial_code_V1.0_QSPI_G2.2_20250606（6代线）(1).c`。

对比对象：替换前的 `SDK/apps/watch/bringup/jd9855_panel_init.h` 临时序列，由 `lcd_qspi_jd9855.c` 的 `REGISTER_LCD_DEVICE(jd9855)` 使用。下文“当前”指此次替换前的快照。

移植状态（2026-09-28）：用户确认采用厂家序列后，已完整替换该头文件；54 个执行事件（50 条命令、4 段延时）与厂家文件逐事件一致。背光恢复固定 80%，其余 QSPI/复位配置和 360×360 几何保持。

## 结论

差异明显，应该优先采用厂家这套完整序列进行下一轮验证。当前序列来自另一份 JD9855 360×360 示例，源码明确标为 provisional，不能代表 BOE1.8-N81 模组参数。

两份各有 50 次命令写入，但不能按行号一一对齐：有分页、增删命令、重复写入和顺序变化。按 `0xDE` 选择的页号与命令编号对齐，并比较同页同命令的最后一次参数，共有 **25 组共有命令参数不同**。

其中页 0 的 `0xC8` Gamma 参数从当前 **16 字节**变为厂家 **32 字节**。页 0 的 `0xBB` 参数也不同，厂家在该命令旁明确注释 `VGH=12V, VGL=-11.5V`。这些差异足以说明需要先替换模组初始化参数；尚不能证明它们就是无画面的唯一原因，也不能据现有测试判定板子硬件损坏。

## 新增、缺失与执行顺序

厂家有而当前初始化表没有的写入：

- 页 0：`D7 = 00 30`。
- 页 1：`D2 = 02 03 52 DF DD`。
- 返回页 0 后：`4D=00`、`4E=00`、`4F=00`、`4C=01`，延时 10 ms，再 `4C=00`。当前初始化表缺少整个步骤。当前驱动的可选内部 RAM 填充诊断代码中存在同组命令，但 `DEMO_LCD_INTERNAL_RAM_FILL=0`，不能当作初始化时已经执行。

当前有而厂家提供文件没有的写入：

- 开头 `01`，随后延时 20 ms，以及 `FF = 20 10 00`。
- 页 0：`D8 = 08 00`。
- 页 1：`C4 = 72 12`、`D4 = 67 00 00 01 00 01`。
- 当前开头预先写过一次 `36=00`、`3A=55`；厂家仅在后段写入。

因此不能只挑几个不同值补到旧表里，否则会保留厂家未要求的写入与旧顺序。移植时应完整转换厂家命令流和延时。

## 相同的关键设置

- 解锁数据 `DF = 98 55` 相同。
- 页 0 的 QSPI 读线选项 `CE = 0D 00` 相同，厂家注释 `00=D1 read; 40=D0 read`。
- 最终 `36 = 00` 相同。
- `3A = 55` 相同；厂家明确注释为 RGB565。因此主要差异不是 RGB565/RGB666 的选择。
- `35` 均为无参数命令。
- `11` 后均等待 120 ms。
- `29` 均存在，但其后当前等待 10 ms，厂家等待 20 ms。
- 页 0 的 `D3/D9`、页 1 的 `BE/C2/D5/D6`、页 2 的 `B6` 参数相同。

## 延时与窗口边界

| 位置 | 当前 | 厂家 |
|---|---|---|
| 表开头 | `01` 后 20 ms | 首个 `DE` 前 10 ms |
| `4C=01` 后 | 无此步骤 | 10 ms，再 `4C=00` |
| `11` 后 | 120 ms | 120 ms |
| `29` 后 | 10 ms | 20 ms |
| `2A/2B` 初始化窗口末值 | `0x0167`，359 | `0x0168`，360 |

厂家文件没有硬件 Reset 脚波形。当前 `lcd_qspi_jd9855.c:53-60` 另有 PC3 复位控制，两者应分开核对。

`0x0168` 与 `0x0167` 是一个确实存在的差异，但不应据此把 Demo 分辨率改成 361×361。当前 SDK 的测试绘制区域使用 `0 .. width-1` / `0 .. height-1`，即 `0..359`；厂家表的窗口末值应在移植时原样保留，并单独观察其与 SDK 后续绘制区域设置的交互。

## 这份文件仍未提供的参数

厂家文件是 `SSD_CMD()` / `SSD_PAR()` / `Delayms()` 调用体，没有这些函数的实现。因此不能仅凭这份文件确认 QSPI 命令封装、时钟极性/相位、最高时钟、像素发送子模式和 Reset 波形。

当前 SDK 的 QSPI 设置仍在 `lcd_qspi_jd9855.c:11-42`：RGB565、SUBMODE1、写命令 `02`、像素子模式命令 `32`。厂家序列与该传输层需要分别验证。
